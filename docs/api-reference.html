B&B AI Enterprise API

OpenAPI 3.1 REST

Overview

The B&B AI Enterprise API powers automated accounting, CFDI processing, collections, billing, and SAT integration for Mexican accounting firms (despachos contables).

📍
Base URL (Production):
https://api.b2b-ai.local/api/v1

Base URL (Development):
http://localhost:8000/api/v1
🔑
Quick Start: All /api/v1/* endpoints require an API key in the X-API-Key header. The /api/v1/leads endpoint is public (no auth needed).

The API follows RESTful conventions. Request bodies use JSON. Responses always include a top-level object. Pagination uses limit query parameter (max 1000). Multi-tenant isolation is enforced: your API key can only access your tenant's data.

Authentication

Two authentication methods: API Key (service-level) and JWT (user-level for portal).

API Key Authentication

Send your API key in the X-API-Key header with every request. API keys are tied to a specific tenant — you can only access data belonging to that tenant.

Request Header
X-API-Key: your-secret-api-key-here
Example: List Invoices
curl -H "X-API-Key: your-api-key" \
     https://api.b2b-ai.local/api/v1/invoices
Response (200)
{
  "count": 42,
  "tenant_id": 1,
  "invoices": [...]
}

JWT Authentication (Portal)

The client portal uses JWT tokens. First register/login to get tokens, then use the Bearer token.

1

Register / Login

POST /api/v1/auth/login with email + password

2

Get Tokens

Receive access_token + refresh_token

3

Use Token

Send Authorization: Bearer <token>

4

Refresh

POST /api/v1/auth/refresh when expired

JWT Login
curl -X POST \
  -H "Content-Type: application/json" \
  -d '{"email": "user@despacho.mx", "password": "secret123", "tenant_id": 1}' \
  https://api.b2b-ai.local/api/v1/auth/login
Response (200)
{
  "user": {"id": 1, "email": "user@despacho.mx", "role": "admin"},
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "refresh_token": "eyJhbGciOiJIUzI1NiIs...",
  "tenant_id": 1
}

Rate Limiting

Protected endpoints are rate-limited per IP + route on a sliding window.

⚡
Default limit: 300 requests per minute per (IP, route) combination.
Exempt paths: /health, /metrics, /static, /docs, /openapi.json, /redoc, /robots.txt, /sitemap.xml, /sw.js, /manifest.json, /favicon.ico

Configure via environment: B2B_RATE_LIMIT_PER_MIN=300 (default). Set to 0 or B2B_RATE_LIMIT=off to disable.

Rate Limit Exceeded Response (429)
{
  "detail": "Demasiadas peticiones. Intenta en un minuto."
}

The Retry-After header indicates when you can retry (in seconds).

Error Codes

Standard HTTP status codes used across all endpoints.

CodeStatusDescription
200OKRequest succeeded. Response body contains the result.
400Bad RequestInvalid request body, missing parameters, or malformed input.
401UnauthorizedMissing or invalid API key / JWT token. Check your X-API-Key header.
403ForbiddenValid credentials but insufficient permissions (e.g., accessing another tenant's data).
404Not FoundResource does not exist (invoice, user, report, etc.).
409ConflictResource already exists (e.g., duplicate email registration).
422Unprocessable EntityValidation error: invalid CFDI, bad period format, missing required fields.
429Too Many RequestsRate limit exceeded. Wait for Retry-After header value.
500Internal ErrorUnexpected server error. Contact support if persistent.
⚠️
CFDI Processing Errors: When uploading an invalid CFDI XML, the API returns 422 with a detail message like "CFDI inválido: ..." explaining the parsing/validation failure.
